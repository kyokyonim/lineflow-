# 03. Pain Point 분석

우선순위 기준: **빈도 × 건당 비용 × 발견 지연** (수치는 가정, 추후 검증 필요)

| 순위 | Pain Point | 빈도 | 건당 비용 | 근거 |
|---|---|---|---|---|
| 1 | 오류를 개통 시점에야 발견 | 오류 전건 (약 20%) | 재승인 3단계 + 롤백 + 신청자 대기 | 승인 3번 후 개통 단계에서 발견 |
| 2 | 요금제 ID 오류·누락을 못 거름 | 알려진 오류 중 최다 (추정) | 6~7분 + 재신청 | 사람이 확인하지 않는 항목과 일치 |
| 3 | LegacyProv 검증 불신뢰 (잘못된 값 통과, 번호 풀 오배정) | 낮음 | 매우 큼 (대량 해지·초기화) | 대량 오배정 사례 |
| 4 | 모호한 오류 → 에스컬레이션 | 낮음 | 1일 이상 | 처음 보는 오류는 문의 대기 |
| 5 | 수기 비교 + 엑셀 기록 | 매 건 | 작음 | 반복 비용 |
| 6 | 연장 수작업 (순차 업로드, 통보서 확인) | 3개월 주기 집중 | 중간 | |
| 7 | 반복 문의 | 미확인 | 작음 | 후순위 |

## 해석
- 1~3번은 모두 "문제를 더 일찍, 더 정확히 발견하는 것"으로 풀린다.
  → 사전 Validation과 개통 직후 결과 검증이 MVP의 핵심.
- 오류 사유가 엑셀 비고(자유 텍스트)에만 있어 **오류 유형별 빈도를 집계할 수 없다.**
  → Error Code 체계와 오류 이력 테이블이 개선 우선순위 판단의 기반.
- 비용을 느끼는 사람(신청자)과 개선을 요구할 사람(운영 측)이 다르다.
  → KPI는 운영자의 처리 시간이 아니라 **신청~개통 리드타임**.
