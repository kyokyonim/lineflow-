# ADR-0006. 규칙은 로직(코드)과 데이터(DB)를 분리

- **상태**: 확정 (MVP)
- **결정**: 검증 알고리즘(로직)은 코드에, 허용 요금제 목록/단말 유형 호환표 같은 값(데이터)은 DB 테이블에 둔다. MVP에서는 초기값을 seed/마이그레이션으로 넣고 관리 화면은 만들지 않는다.
- **배경**: 현재 문제 3은 규칙이 특정 운영 담당자 머릿속에 있다는 것이다. 규칙을 코드에만 두면 특정 개발자에게 의존하는 것으로 문제가 이동할 뿐이다.
- **대안**: 모든 규칙을 코드에 하드코딩 → 요금제 추가마다 배포가 필요하다. 모든 규칙을 관리 화면으로 → MVP 범위 초과.
- **결과**: 관리 화면은 Non-Goal. 데이터는 구조상 나중에 화면을 얹을 수 있다.
