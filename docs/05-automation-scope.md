# 05. 자동화 / 비자동화 범위

| 구분 | 업무 | 비고 |
|---|---|---|
| 자동 | 사전 Validation, 호환성 검증, 데이터 자동 비교, 번호 변경 단계 실행, 이력 기록, 결과 통지, 개통 직후 결과 검증 | |
| 자동 (조건부) | 알려진 오류의 단건 롤백 | 알려진 코드 + 단건 + 대상 정확 매칭 (MVP 이후) |
| 반자동 | 대량 롤백, 예외 요청 | 시스템이 대상과 건수를 미리 보여주고 사람이 확인. 건수 기준(N)은 설정 값 |
| 수동 (시스템 보조) | 미확인 오류 분석 | 에스컬레이션 패키지 제공 |
| 수동 | 팀장 승인 | 권한과 책임 |
| 대상 아님 | 소명서 내용의 타당성 판단 | 현행 정책에 없음. 개선 제안으로만 |
| AI 후보 (후순위) | 매뉴얼 기반 문의 응답 (RAG) | 핵심 기능 안정 후 |

## 판단 원칙
- 우선순위: **예방 > 자동 복구 > 수동 처리** (롤백을 자동화하기보다 롤백이 필요 없게 만드는 것이 싸다)
- 롤백 자동 실행 조건: ① 원인이 확정된 코드 ② 영향 범위가 해당 신청 건으로 한정 ③ 멱등하게 구현
- 원인 불명(`UNKNOWN_PROVISIONING_ERROR`)이면 롤백하지 않고 상태를 보존한 채 사람에게 넘긴다 (증거 보존)
- 두 종류의 실수: 잘못된 신청을 통과시키는 것(재작업 비용 큼) vs 정상 신청을 거절하는 것(신청자 불편).
  규칙을 엄격히 할수록 후자가 늘어나므로 **예외 요청 경로(탈출구)**를 둔다.
- 자동화 가능 여부는 연동 인터페이스(API, 업로드, 조회)의 존재에 달려 있다.
  가상 LegacyProv는 업로드/조회/삭제 API를 제공하는 것으로 정의한다.
