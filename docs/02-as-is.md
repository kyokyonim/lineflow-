# 02. As-Is 프로세스 (현재 업무)

> As-Is = 현재 있는 그대로의 업무 방식. (To-Be = 개선 후 모습)
> 수치는 가정이며 실제 수치가 아닙니다.

## 흐름
```
[신청자]          ApprovalHub에서 신청 (신규/연장/해지)        ※ 입력 검증 없음
   ↓
[신청자 팀장]     1차 승인
   ↓
[운영 담당자]     승인 단계: 결재 첨부 양식 ↔ LegacyProv 입력 정보를 눈으로 비교
                  (회선 수, 단말기 정보 중심) → 승인 → 엑셀 현황 대장에 기록
   ↓
[운영 팀장]       최종 승인
   ↓
[운영 담당자]     LegacyProv에서 개통 처리
   ↓
   ├ 성공 → 완료
   └ 실패 (정합성 검사 오류 / 모호한 메시지)
        ├ 알려진 오류: 약 6~7분 (원인 확인 → 롤백 3종 → 통보)
        ├ 처음 보는 오류: 담당자 문의 → 하루 이상
        ├ 롤백: 미완료 데이터 삭제 / USIM 초기화·재사용 / 신청자 통보
        ├ 엑셀 비고란에 사유 기록 (자유 텍스트)
        └ 재신청 → 승인 3단계 처음부터
```

## 검증 시점 현황
| 시점 | 현재 |
|---|---|
| 신청 시점 | 검증 없음 |
| 개통 직전 | 사람이 눈으로 비교 (요금제 ID 등 놓침) |
| 개통 처리 | LegacyProv 정합성 검사 (불완전: 잘못된 요금제도 통과하는 경우 있음) |
| 개통 직후 | 결과 검증 없음 |

## 핵심 수치 (가정)
- 신규 신청 일 약 5건, 연장은 3개월 주기로 집중 발생
- 한 신청당 회선 5~100개
- 첫 시도 통과율 약 80% (추정)
- 오류 1건 비용: 알려진 오류 6~7분, 미확인 오류 1일 이상 + 재승인 3단계
- 과거 사례(가상 일반화): 대량 신청에서 전용 번호 풀 단말에 일반 번호가 배정되어 전량 해지·초기화

## 연장 업무 (현재)
- 연장 기간은 최대 3개월
- 유형: 번호 변경(기본, 사규) / 번호 유지(예외, 사내 통보서 첨부 필수)
- 번호 유지 시 통보서 누락 → 결재 후 신청자에게 안내하거나 메일로 수령 후 엑셀 비고에 기록
- 번호 변경 → 변경 항목(신청자 / 사용자 / 사용 종료일)을 **한 번에 하나씩** 순차 업로드 (LegacyProv 제약: 동시 변경 시 데이터 꼬임)
  - 변경 내용이 이전과 같으면 LegacyProv가 에러를 반환 (= 해당 항목은 변경 불필요라는 신호)
- 완료 후 이전 번호 → 새 번호, 종료일 변경 내역을 신청자에게 전달 (다운로드 제공)
